## Goal

Let the catalogue say that a service needs named Docker volumes, and mount them in `docker run`, so state that must survive `docker rm -f` (stt's model cache) can live outside the container (F8). **Written for option B of T-02.1.**

## Specification

- A service without `volumes` produces exactly the same `docker run` line as before (a test compares it).
- The volume is created by Docker on first use; the tool never creates, prunes or removes volumes, and `stop` / `rm -f` do not touch them.
- Native runtime ignores `volumes`.
- Do not add the stt entry here (T-02.4) and do not change `.env` handling: the generated file is still bind-mounted read-only at `/app/.env`.
- Every command goes through `Shell`; `--dry-run` has no side effect (there is a test).

## Acceptance criteria

- A catalogue test: a service declared with `volumes = { models = "/models" }` loads it; one without has `{}`.
- A `docker run` test: the line for that service contains `--mount type=volume,source=oblivion-<service>-models,target=/models` and still contains the `.env` mount; the line of a service without volumes is unchanged.
- The deployment suite passes.

## Verification

Run the deployment tests in the background. The real behaviour (a volume that keeps its content across `docker rm -f`) is proved in [T-03.3](../T-03_docker-and-arm64-acceptance/T-03.3_restart-without-redownload.md), because it needs Docker.

## Result (2026-11-09)

Done in `deployment/`: `ServiceSpec.volumes` (suffix to path), read by `catalogue_loader.py`; `docker_runtime.volume_name()` and a shared helper `_settings_and_volumes()` that gives `start` the `.env` mount and one `--mount type=volume,source=oblivion-<service>-<suffix>,target=<path>` per volume. A service without volumes gets exactly the `docker run` line it got before (a test compares the whole line for tts); `stop` and `rm -f` never touch a volume; native ignores the key. The header table of `config/catalogue.toml` has the new row. Tests: `deployment/tests/test_docker_volumes.py` (23 cases for T-02.2 to T-02.4). Not run with a real Docker: that is T-03.3.
