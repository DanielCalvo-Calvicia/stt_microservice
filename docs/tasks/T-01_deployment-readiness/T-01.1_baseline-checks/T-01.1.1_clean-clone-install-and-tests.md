## Goal

Install the service from a **clean clone** of the pushed branch and run the suite, to prove that what is in git is enough (F1, F2, F3).

## Read first

[../../../deployment/deployment.md](../../../deployment/deployment.md) ("Run by hand"), facts F1, F2 and F3 of the [tasks README](../../README.md).

## Files

None changed. The clone lives outside the workspace (the scratchpad or a temporary folder), never inside `stt_microservice`.

## Steps

1. Confirm what is pushed: `git -C stt_microservice status -sb` and `git -C stt_microservice log origin/feature_ai_claude_2 -1`. The clone has the pushed commit, not the uncommitted `contracts` 0.16.0 edit of F1; write that difference down.
2. Clone into a new empty folder, next to a copy of `shared-logging` (it has no repository), so that `-e ../shared-logging` resolves:
   ```powershell
   git clone --branch feature_ai_claude_2 https://github.com/DanielCalvo-Calvicia/stt_microservice.git <temp>\stt_microservice
   Copy-Item -Recurse D:\Hobbys\IA\OBLIVION\shared-logging <temp>\shared-logging
   ```
   Do not copy a `.env` or a `windows` venv into the clone.
3. In the clone: create a venv with the interpreter of the service venv (read `windows\pyvenv.cfg`), then `windows\Scripts\python.exe -m pip install -r requirements.windows.txt`. Note whether anything is compiled and which versions of fastapi, numpy, faster-whisper, ctranslate2 and onnxruntime resolve.
4. Try once the install **without** the sibling folder to record how it fails (F3): it should stop at `-e ../shared-logging` before downloading anything.
5. `windows\Scripts\python.exe -m pytest` in the clone.
6. Delete the temporary folder.

No model is downloaded by this task (the suite fakes the engines).

## Acceptance criteria

- The install finishes without compiling anything (shared-logging, a local pure-Python package, is the only thing built) and without a warning about a missing package.
- The suite passes with the same count as the working folder (90 on 2026-11-06) or with a difference explained in *Notes*.
- The failure of the lone-clone install is recorded.

## Verification

The three results above, pasted into *Notes* (not the whole pip log).

## Notes

Expected finding (F3): `pip install -r requirements.windows.txt` on a lone clone stops on `-e ../shared-logging`; the deployment tool works around it.

## Result (run on 2026-11-06)

Run by the assistant after the maintainer said "go". Windows 11, the interpreter of the service venv (CPython 3.14.2, `windows\pyvenv.cfg`), in a throw-away folder in the session scratchpad (deleted at the end). Nothing was changed in the repository; no model was downloaded and no network call was made except cloning and installing packages.

1. **What is pushed.** `origin/feature_ai_claude_2` is at `853d1bf` ("Bundle contracts 0.15.0"). The working folder is one commit **ahead** (`bcd76a0`, "Restructure the documentation like dynamics_microservice", only `CLAUDE.md`, `README.md` and `docs/`; not pushed) and has the uncommitted edits of F1 (`contracts` 0.16.0 lines in both requirement files, the 0.15.0 wheel deleted, the 0.16.0 wheel untracked). The clone therefore holds `853d1bf` with the **0.15.0** wheel; the difference touches no code or tests.
2. **Lone clone (step 4, run first).** `pip install -r requirements.windows.txt` with no `shared-logging` next to the clone stops at once with `ERROR: ../shared-logging is not a valid editable requirement` and installs nothing (the venv still had only `pip`). F3 confirmed. The clone and the sibling were then put together (a copy of `shared-logging` without its old `build/`, `*.egg-info` and caches).
3. **Install.** Exit 0, no warning lines, 187 log lines. The only thing built was `shared-logging` (an editable wheel, pure Python); everything else came as binary wheels. Resolved versions: fastapi 0.162.0, uvicorn 0.54.0, pydantic 2.14.3, numpy 2.5.4, openai 3.46.0, faster-whisper 1.2.1, ctranslate2 4.8.5, onnxruntime 1.31.1, huggingface_hub 2.4.0, httpx 0.28.1, contracts-microservice 0.15.0, shared-logging 0.1.0, pytest 9.2.0. These are the versions T-01.6 will see as a first reference (they are **not** proof that the real engines work: no engine was run here).
4. **Tests.** `windows\Scripts\python.exe -m pytest -q` in the clone: **90 passed in 6.72 s**, the same count as the working folder on 2026-11-06.
5. The temporary folder was deleted.

- `pip list` in the clone shows pytest, black and mypy (and `httpx2`/`httpcore2`, which came with the newer `openai` 3.x); the runtime install carries the dev tools, as debt 2 says (T-01.4).
- `httpx` and the other packages are all `>=` bounds, so this install got the newest releases of 2026-11-06; a deploy next month may get others (T-01.6).
