## Goal

Prove that the service deployed by T-01.1.2 transcribes real speech with the **local** engine and the **gate**, and that its probes and log lines say what the documents say (F4, F12). The unit tests only use fake models; the real model has not been loaded in the last documentation pass.

## Read first

[../../../api/api.md](../../../api/api.md) (batch route, gate routes), [../../../operations/monitoring.md](../../../operations/monitoring.md) (probes and log lines), `contracts/tests/e2e/make_speech.py` (F18).

## Files

None changed in the repositories. The WAV and its raw PCM live in the session scratchpad, never in the workspace.

## Steps

1. Make an input: with the tts venv, `tts_microservice\windows\Scripts\python.exe contracts\tests\e2e\make_speech.py "Oblivion 306, what time is it" <scratch>\phrase.wav` (run from the workspace root; Windows uses the SAPI voice). Strip the 44-byte WAV header to get raw PCM16 mono and read the sample rate from the header (a short PowerShell or Python snippet written with the Write tool in the scratchpad).
2. The base URL is the stt address in the layout (`<stt-base-url>`: host and port from `oblivion.py status`/`plan`; do not assume `127.0.0.1`).
3. Probes: `GET <stt-base-url>/health`, `/available`, `/gate/available`. Record the bodies.
4. Main engine: `POST <stt-base-url>/process/batch?sample_rate=<rate>` with the raw PCM as the body (no JSON, no particular content type). Expected: `data.text` is the phrase, to the quality of `small.en`. Record the text and the elapsed time. Repeat with an **empty** body: expected `400`.
5. Gate: send the same utterance to `POST <stt-base-url>/gate/process/stream/set` as NDJSON `stream_started` + one `utterance` event built with `contracts.stream.codec` (a small script written with the Write tool in the scratchpad, run with the stt venv; never hand-write event JSON), then read `GET <stt-base-url>/gate/process/stream/get` with `Accept: application/x-ndjson`. Expected: a `completed` event whose text carries the wake phrase and whose `audio_base64` is the utterance.
6. Log lines: `oblivion.py logs --host <machine> -s stt --lines 80` shows `Loading local Whisper model on CPU with int8 compute`, `Local Whisper model loaded` (twice: main and gate), `Batch transcription completed` with **lengths only**, no text and no audio (NFR-4).
7. Optionally run `stt_microservice\tests\simple.py` (F18) against the service: it only checks `/health` and `/available` (read on 2026-11-06), and has `127.0.0.1:8001` hard-coded, so it only works when run on the machine of the service.

## Acceptance criteria

- `/available` and `/gate/available` answer `is_available: true`.
- The batch route returns the expected phrase (or a close one: record both) and the gate returns a `completed` event with `audio_base64`.
- The empty body gives `400`.
- The log shows the model lines and no utterance text.

## Verification

The probe bodies, the transcribed text, both timings and the log lines, pasted in *Notes* (no audio).

## Result (run on 2026-11-06)

Run by the assistant after the maintainer said "go", on the scratch deployment of T-01.1.2 (`C:\stt_t0112`, started again with `oblivion.py start`; `STT_ENGINE=local`, gate on, no key). Machine: Windows 11, Intel Core i7-14700K (20 cores, 28 threads), 31.8 GB RAM. The service listened on `http://127.0.0.1:8001` (the all-in-one layout on this machine; taken from `plan`). Input: two spoken WAVs made with `contracts/tests/e2e/make_speech.py` and the tts venv (SAPI English voice, mono, 22050 Hz): `phrase.wav` (3.78 s, "Oblivion 306, what time is it") and `other.wav` (2.11 s, "The weather is nice today"). The probe script `C:\stt_t0112\probe.py` built the uploads with `contracts.stream.codec` (no hand-written event JSON) and ran with the stt venv. Nothing in the repositories was changed; no audio is pasted here.

**Probes:** `/health` 200 `{"healthy": true}`; `/available` 200 `{"is_available": true, "reason": null}`; `/gate/available` 200 `{"is_available": true, "reason": null}`.

**Batch route, `small.en` (raw PCM body, `?sample_rate=22050`):**

| Audio | Text returned | Elapsed (two calls) | Real-time factor |
|---|---|---|---|
| `phrase.wav`, 3.78 s | ` Oblivion 306, what time is it?` | 5.01 s, 4.85 s | 1.32, 1.28 |
| `other.wav`, 2.11 s | ` The weather is nice today.` | 4.57 s, 4.48 s | 2.17, 2.12 |

The text is exactly what was said. The batch text starts with a space (the engine's output, which `api.md` already says is returned as produced); the same utterances through the main shared stream came back without it. An **empty** body gave `400` `No audio data provided`.

**Main shared stream** (`/process/stream/set` then `/get`, NDJSON): `stream_started`, `partial`, `completed` with the same text (stripped) and `audio_base64` empty, as documented (FR-11, FR-21). Round trip 4.84 s and 4.44 s.

**Gate, `tiny.en`** (`/gate/process/stream/{set,get}`): `completed` with `Oblivion 306. What time is it?` for the first phrase and `The weather is nice today.` for the second (the gate engine does **not** decide the wake phrase; Brain does), each carrying `audio_base64` that decodes to exactly the input PCM (`audio_equals_input=True`). Round trip 0.72 s and 0.67 s (real-time factors 0.19 and 0.32).

**Log (NFR-4):** no line of the service log contains the spoken text (a search for both phrases found 0 hits). The lines per utterance are `Decoded STT utterance event` (sequence, bytes, sample rate), `Resampling audio to the Whisper sample rate` (22050 to 16000), `Utterance transcribed` (`text_length`, `audio_bytes`, `sample_rate`) and, for the batch route, `Batch transcription completed` (`text_length` only). The two `Loading local Whisper model on CPU with int8 compute` and `Local Whisper model loaded` lines (main and gate) are in the T-01.1.2 result.

**`tests/simple.py`** (from the clone in the work directory, with the stt venv): it first crashed with `UnicodeEncodeError` printing its box-drawing characters on a Windows console with the cp1252 code page; with `python -X utf8` it passed both checks (`/health`, `/available`), as read on 2026-11-06.

### Findings

1. **The cost of `small.en` is almost flat in the length of the utterance:** about 4.5 to 5 s for a 2.1 s clip and for a 3.8 s clip, with 2 threads, `int8`, on a very fast desktop CPU. The likely cause is Whisper's fixed 30 s input window (a short clip is padded), so the real-time factor is worse for short utterances (2.1 here). **This is the number T-03.6 compares with the Pi**, where it will be several times slower; it also means `STT_THREADS` (T-01.2) is the first thing to tune. The cause is a hypothesis, not measured.
2. The gate (`tiny.en`) is about 6 to 7 times faster than the main model (0.7 s against 4.5 to 5 s) on the same machine.
3. The main model dominates: Brain gets the text of an utterance about 5 s after it ends on this machine with the local engine. Whether that is acceptable is the maintainer's call (Q01-7: no time limit given), so this task only reports it.
4. Memory use during a call was not measured (not asked by the acceptance criteria); T-03.6 measures it on the Pi.
5. The batch text keeps a leading space while the stream text does not (documented in `api.md`); a caller that compares texts must strip.
6. `tests/simple.py` needs `-X utf8` on a Windows console and checks only `/health` and `/available`; it does not transcribe anything.
