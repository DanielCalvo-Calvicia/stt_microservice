### Corrections and consequences

- **A wrong statement in this task's own Specification (point 2) is corrected here:** it said `httpx` leaves the runtime file because "`openai` depends on it, so it is installed anyway". With `openai` 3.46.0 the runtime venv has **`httpx2` and `httpcore2`, not `httpx`** (`import httpx` fails there). That is harmless, because no file of the service imports `httpx` (only the tests and `tests/simple.py` do, and the dev file lists it), but it means `httpx` is a dev-only dependency now. The comment in `requirements.dev.txt` says so. The fact F2 of the plan has the same note.
- **Existing venvs keep the tools.** Changing the requirement file changes the tool's fingerprint, so the next `deploy` or `update` reinstalls the dependencies, but `pip install -r` does not uninstall anything: a venv built before this change (the maintainer's `~/oblivion/venvs/stt`, the scratch one) still has pytest, ruff, black and mypy until it is rebuilt. New venvs and new Docker images do not.
- Pinning is T-01.6, not here. The `contracts` 0.16.0 line stays uncommitted (yours); the stt documents still say 0.15.0, the committed version, until you commit it.
