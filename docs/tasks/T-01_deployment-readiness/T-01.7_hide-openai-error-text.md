## Goal

With a wrong OpenAI key, the library's 401 message (`Incorrect API key provided: <first 8 characters>***...<last 4 characters>`) reaches the caller in the failure envelope and the log. T-01.1.5 verified it on 2026-11-06 with a fake key (drill 5). Make the OpenAI engine raise an error with a **fixed message** (the exception type and the HTTP status, nothing else), so no text of the library, and so no part of a key, leaves the engine, whether it ends in an HTTP answer, a stream `error` event or a log line. The maintainer asked for it ("Yes, add the task", answer to the question at the end of T-01.1.5).

## Specification

1. **The message.** In `OpenAIWhisperTranscription.transcribe_batch`, catch `openai.OpenAIError` around the `asyncio.to_thread(_call_whisper_api, ...)` call (the family that holds `AuthenticationError`, `RateLimitError`, `APIStatusError`, `APIConnectionError`, `APITimeoutError`) and raise `TranscriptionFailed` with exactly `OpenAI request failed: <ExceptionClassName> (HTTP <status>)` when the error has an integer `status_code` (for example `OpenAI request failed: AuthenticationError (HTTP 401)`), and `OpenAI request failed: <ExceptionClassName>` when it has none (for example `APIConnectionError`). Raise it `from None`, so neither `__cause__` nor `__context__` prints the library text in a traceback (`logger.exception` in `SttService` logs the traceback).
2. **Nothing else is caught.** Any other exception (a `ValueError`, an `OSError` from the temporary WAV) is not an OpenAI error and passes through unchanged. The temporary WAV is still removed on failure (the `finally` stays).
3. **No new log text with the library's message.** The adapter logs at most `logger.warning("OpenAI request failed", error_type=..., status_code=...)`; keep the existing `Calling OpenAI transcription API` and `OpenAI batch transcription completed` lines as they are.
4. **Status.** `TranscriptionFailed` maps to `500` by the existing default of `map_error`. Do not change the status (a `502` would be a change of the API and the maintainer did not ask for it).
5. **The key.** `self._api_key` is never put in a message, a log field or an exception attribute. If a test needs it, it uses an obviously fake value.
6. The `domain` and `application` layers do not import `openai` (the architecture test enforces it): the adapter imports `TranscriptionFailed` from `application.errors`, which is allowed for `infrastructure/outbound`.

## Tests (add; do not weaken existing ones)

- **Engine:** with the module's `OpenAI` replaced by a fake client whose `audio.transcriptions.create` raises `openai.AuthenticationError(message="Error code: 401 - Incorrect API key provided: sk-fake-*****0000.", response=httpx.Response(401, request=httpx.Request("POST", "https://api.openai.com/v1/audio/transcriptions")), body=None)`: `transcribe_batch` raises `TranscriptionFailed` whose text is exactly `OpenAI request failed: AuthenticationError (HTTP 401)`; the text contains neither `sk-` nor the engine's api key; `error.__cause__ is None` and `error.__suppress_context__ is True`; the temporary WAV file is gone.
- **Engine, no status:** an `openai.APIConnectionError(request=...)` gives `OpenAI request failed: APIConnectionError`.
- **Engine, pass-through:** a `ValueError` raised by the fake client is **not** wrapped.
- **HTTP batch:** build the app with the real `OpenAIWhisperTranscription` (fake client as above) and `POST /process/batch`: status `500`, and neither `message` nor `data` contains `sk-`, `fake` or the text of the library; `message` is `Failed to process batch: OpenAI request failed: AuthenticationError (HTTP 401)`.
- **Log:** the same call logs `Operation failed` with an `error` that has no key text. Capture logs the way the existing tests do (read `tests/` first); if there is no precedent, replace `http_envelope.logger` with a recorder for the test.
- **Stream:** a `set` with one utterance and the same engine, then `get`: the `error` event's `message` is `OpenAI request failed: AuthenticationError (HTTP 401)`, with no library text.
