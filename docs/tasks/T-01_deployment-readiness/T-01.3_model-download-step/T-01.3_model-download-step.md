## Goal

Make the deploy tool's `prepare` step (`scripts/fetch_gate_model.py`) download **every** local model the settings make the service load, not only the gate's, and pin its behaviour with tests. Today it is the only step between a deploy and a ready model, it had no test until T-01.3.1 (F5), and it never loads the main model (debt 3). On a native install the first start otherwise downloads `small.en` while Brain's 60 s preflight and the deploy's 60 s health wait are running (F13).

## Why this is not the whole Docker answer

In a container the script runs at *build* time with no `.env`, so it fetches nothing whatever it is taught (F7). That half is [T-02](../../T-02_deployment-tool-changes/T-02_deployment-tool-changes.md); this group only makes the script right for the native path and for whoever runs it with the real settings (the run-time step of T-02.3).

## Exit criteria

Running the script with `STT_ENGINE=local` downloads the main model, with the gate on it also downloads the gate's, and its exit codes (0 ready or not needed, 1 a model could not be loaded) are covered by tests that need no network.
