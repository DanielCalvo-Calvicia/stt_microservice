## Specification

The script is not a package and inserts its folder into `sys.path` at import time: load it with `importlib.util.spec_from_file_location` from the repository root. It imports `faster_whisper` **inside** `main()`, so replace it with `monkeypatch.setitem(sys.modules, "faster_whisper", types.SimpleNamespace(WhisperModel=fake))`. Replace the module's `load_dotenv` with a no-op in a fixture: the service folder has a real `.env` that no test may read. Set the settings with `monkeypatch.setenv` / `delenv`. No network, no real model.

Cases, each a test:

1. Gate off (default): exit 0, the output says no gate model is needed, the fake `WhisperModel` is never called.
2. Gate on: the fake is called once with `STT_GATE_MODEL` and `device="cpu", compute_type="int8"`; exit 0; "ready" printed.
3. The fake raises (no network, a mistyped name, a full disk): exit 1, the message goes to stderr.
4. `STT_ENGINE=local` with the gate off: **today** exit 0 and the fake is never called. Name the test so it says it records the current gap (`..._does_not_fetch_the_main_model_yet`); T-01.3.2 turns it around.
5. `STT_GATE_ENABLED` accepts `1`, `true`, `yes` and `on` as `SttConfig` does (one parametrised test).

## Acceptance criteria

All five cases pass and each fails if the corresponding line of the script is changed. The exit codes stay 0 and 1; no new exit code is introduced. The suite passes with the new total.

## Verification

`windows\Scripts\python.exe -m pytest tests\scripts` then the whole suite; record the new total.

## Notes

The audit's claim "`prepare` fetches the gate's model only when `STT_GATE_ENABLED=1`" is case 1 and 2 of this task; "it never fetches the main model" is case 4.

- Case 4 (`..._does_not_fetch_the_main_model_yet`) must be turned around, and a case for "local engine with the gate on fetches both models" added. The exit codes stay 0 and 1.
