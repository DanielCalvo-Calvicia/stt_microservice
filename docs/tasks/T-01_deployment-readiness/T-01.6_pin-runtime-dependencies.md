### One decision I took that you may want to veto: the `numpy` line

A first dry-run showed that `numpy==2.5.4` **does not exist for Python 3.11** (the newest 3.11 build is 2.4.6), while the other six pins resolve on 3.11. A Raspberry Pi OS on Debian bookworm has Python 3.11, and `pyproject.toml` targets 3.11, so an unconditional pin could have broken an install that works today. The line therefore has an environment marker: the proven pin from Python 3.12 (the deploy image, the workspace venv and a `python3.12` Pi machine file all qualify) and, **below 3.12, the old open bound**, which is unchanged and **not proven**. If you want 3.11 unsupported instead, delete the second `numpy` line.
