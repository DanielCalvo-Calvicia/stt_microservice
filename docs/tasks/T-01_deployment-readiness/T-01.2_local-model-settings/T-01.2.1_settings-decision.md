## Goal

Decide the names, the sharing between the main model and the gate, and the policy for a bad value of the new local-model settings. They become part of the service's configuration interface, which the deployment tool, its manual and every operator then use.

## Facts

- Today: `DEFAULT_MODEL_NAME = "small.en"`, `WhisperModel(model_name, device="cpu", compute_type="int8", cpu_threads=2)` (F4). The main model and the gate share the same class and so the same device, compute type and threads. `SttConfig` has `gate_model` but no `model`.
- The audit recommends `STT_MODEL`, `STT_THREADS`, `STT_COMPUTE_TYPE`, defaults equal to today's values, the same threads and compute type for the gate, and a start-up error for a non-numeric or negative thread count ([../../../deployment_audit/stt.md](../../../deployment_audit/stt.md), recommended change 1).
- The existing configuration has no validation of its values except `SERVICE_PORT`, which stops the start with a `ValueError` ([../../../configuration/environment-variables.md](../../../configuration/environment-variables.md)). An unknown model name fails when the model is loaded (`LocalEntryNotFoundError` offline; a download error online).
- On a 4-core Raspberry Pi the main model (2 threads) and the gate (2 threads) can run at the same time (the main stream, the batch route and the gate are independent, [../../../architecture/architecture.md](../../../architecture/architecture.md) section 7).
- `deployment/docs/DEPLOYMENT.md` and `config/services/stt.toml` list the settings, so a name chosen here is copied there (T-02.5) and into Brain-side documentation by the operator. Renaming later costs more than choosing now.

## Options

| | Option | Cost | Notes |
|---|---|---|---|
| A | `STT_MODEL` (main model), `STT_THREADS` and `STT_COMPUTE_TYPE` shared by the main model and the gate; blank = default; a bad `STT_THREADS` stops the start with a `ValueError` naming it; `0` = let ctranslate2 choose | smallest; 3 variables | the audit's recommendation; the gate cannot get a different thread count |
| B | A plus `STT_GATE_THREADS` and `STT_GATE_COMPUTE_TYPE` (blank = the shared value) | 5 variables, more documentation and tests | lets a Pi give 1 thread to the gate and 3 to the main model |
| C | A, but a bad value is replaced by the default with a warning in the log | same as A, less strict | hides a typo (`STT_THREADS=four` silently runs with 2) |

The device stays `cpu` in every option; a `cuda` option is not asked for (the robot's machines are CPU-only, [../../../deployment/deployment.md](../../../deployment/deployment.md)).

**Recommendation: A.** It is the smallest change that closes debt 1 and matches the audit; B can be added later without renaming anything (the shared values are its defaults); C hides mistakes, and the service already fails fast on its other bad start-up values.

## Questions for the maintainer

1. A, B or C?
2. Should a bad `STT_THREADS` stop the start (recommended) or fall back to the default?
3. `STT_COMPUTE_TYPE` is passed to ctranslate2 as given (lower-cased and trimmed); the service does not keep a list of valid names, so an unsupported one fails when the model loads. Is that acceptable? (Recommended: yes; the list depends on the CPU and the ctranslate2 version.)
4. Any other name you prefer for the three variables? (`STT_MODEL` also names the OpenAI model in some projects; here the OpenAI model stays the constant `whisper-1`.)

## Resolution

**Decided by the maintainer on 2026-11-06, in chat: option A on every question.**

1. **Shape: A.** `STT_MODEL` (the main model), `STT_THREADS` and `STT_COMPUTE_TYPE`, the last two shared by the main model and the gate. No separate gate settings now; they can be added later without renaming (the shared values would be their defaults).
2. **A bad `STT_THREADS` stops the start** with a `ValueError` that names the variable. `0` is valid and means "let ctranslate2 choose"; a blank value is the default `2`.
3. **`STT_COMPUTE_TYPE` is passed through** (trimmed and lower-cased); the service keeps no list of valid names, so an unsupported one fails when the model loads.
4. **Names kept:** `STT_MODEL`, `STT_THREADS`, `STT_COMPUTE_TYPE`. The OpenAI model stays the constant `whisper-1`.

Reasons: the smallest change that closes debt 1 and matches the audit; the service already fails fast on its other bad start-up values; the valid compute types depend on the CPU and the ctranslate2 version.
