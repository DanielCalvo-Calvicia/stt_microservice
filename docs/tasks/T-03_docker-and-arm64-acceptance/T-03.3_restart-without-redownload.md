## Goal

Prove the audit's main Docker claim: a recreated container no longer downloads the model. This is the acceptance test of NFR-9.

## Read first

[T-03.2](T-03.2_run-and-call.md), `deployment/infrastructure/outbound/runtime/docker_runtime.py` (`start` removes the container first), F8 of the [tasks README](../README.md).

## Files

None changed.

## Steps

1. Starting from the state of T-03.2 (models in `oblivion-stt-models`), note the size of the volume's content (`docker --context desktop-linux run --rm --mount type=volume,source=oblivion-stt-models,target=/models --entrypoint du <image> -sh /models`).
2. `docker --context desktop-linux restart oblivion-stt`: wait for `/available`; read the log: no download.
3. Recreate it: `oblivion.py stop --host <machine> -s stt` then `start` (the tool does `docker rm -f` and `docker run`). Time how long `/available` takes to answer and read the log again.
4. Prove it without trusting the log: run a throw-away container **with the network disabled** that loads the model from the volume:
   ```powershell
   docker --context desktop-linux run --rm --network none --mount type=volume,source=oblivion-stt-models,target=/models -e HF_HOME=/models/huggingface --entrypoint python oblivion/stt:local -c "from faster_whisper import WhisperModel; WhisperModel('small.en', device='cpu', compute_type='int8'); print('loaded from the volume')"
   ```
   (use the model names and the `HF_HOME` the settings and the catalogue really use).
5. `oblivion.py deploy` again (a rebuild of the image) and confirm the volume content is unchanged and the first start is as fast as step 3.

## Acceptance criteria

- Steps 2 and 3 show no download and a start time close to the native cached start.
- Step 4 prints the success line with the network disabled.
- The volume's size is the same before and after.

## Verification

The log excerpts, the timings, the `du` outputs and the step 4 output, in *Notes*.

## Notes

If a download happens anyway, check that `HF_HOME` in the container really points into the volume (`docker exec oblivion-stt printenv HF_HOME`, which prints a path, not a secret).

## Result (2026-11-09)

The volume held **551,212 KiB** before and after every step below. **Step 2, `docker restart`:** `/available` answered after **3.1 s**, 0 download lines in the log. **Step 3, recreate with the tool** (`oblivion.py stop` then `start`: `docker rm -f` and `docker run`): healthy in **5.4 s** (the tool's `start` call, including its health wait), both models loaded 0.4 s apart, 0 download lines. **Step 4, network disabled:** `docker run --rm --network none --mount type=volume,source=oblivion-stt-models,target=/models -e HF_HOME=/models/huggingface --entrypoint python oblivion/stt:local -c "WhisperModel('small.en'...); WhisperModel('tiny.en'...)"` printed `loaded from the volume, no network`. **Step 5, `deploy` again (a rebuild of the image):** 73 s in total (the build, then `Main model small.en is ready` and `Gate model tiny.en is ready` at once, no download), volume unchanged, 0 download lines, healthy. **NFR-9 is met on amd64 with Docker Desktop.** Two slips of the assistant's own script, not findings: `oblivion.py start` has no `--health-timeout` option (it made the first scripted run wait forever for a container that was never created), and Git Bash rewrote `/models` into a Windows path until `MSYS_NO_PATHCONV=1` was set.
