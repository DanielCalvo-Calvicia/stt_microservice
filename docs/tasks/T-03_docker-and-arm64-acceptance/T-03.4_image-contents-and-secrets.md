## Goal

Prove two audit claims about the image: it carries no dev tools (debt 2) and no secret (the `.env` is excluded from the build context and only bind-mounted at run time). The audit read these in the code; nothing was built.

## Read first

`deployment/infrastructure/outbound/runtime/docker_runtime.py` (`prepare_context` ignore list, `start`), [../../security/security.md](../../security/security.md), F8.

## Files

None changed.

## Steps

All the searches below are for the **absence** of a name or a prefix; count the matches and print nothing that could be a value.

1. Dev tools: `docker --context desktop-linux run --rm --entrypoint pip oblivion/stt:local list` and look for `pytest`, `ruff`, `black`, `mypy` (expected: none; `httpx` is present because `openai` needs it).
2. Files: `docker --context desktop-linux run --rm --entrypoint ls oblivion/stt:local -la /app`: no `.env`, no `windows`, no `.git`.
3. History and config: `docker --context desktop-linux history --no-trunc oblivion/stt:local` and `docker --context desktop-linux inspect oblivion/stt:local` piped to a search for `OPENAI_API_KEY` and `sk-` (count only: expected 0). Do the same on the running container's `inspect` (its `Config.Env` has no key because the settings arrive through the mounted file) and confirm it shows the `.env` as a read-only bind mount and the models as a volume.
4. The mounted `.env` is not a layer: `docker --context desktop-linux save oblivion/stt:local | tar -t` listing has no `.env` entry (list names only).
5. The image runs as which user (`docker inspect ... .Config.User`): record it (the Dockerfile sets none, so root; a finding for [../../security/security.md](../../security/security.md), not a fix of this task).

## Acceptance criteria

Steps 1 to 4 find nothing; step 3 on the running container shows the read-only `.env` bind mount and the volume; the user of the process is recorded.

## Verification

The counts and the listings, in *Notes*. If anything is found, stop and tell the maintainer before pasting any detail.

## Notes

## Result (2026-11-09)

1. **Dev tools:** `pip list` in the image has none of pytest, ruff, black, mypy (0 matches); `faster-whisper 1.2.1`, `openai 3.46.0` and `httpx2 2.16.0` (not `httpx`) are there. 2. **`/app`:** no `.env`, no `windows`, no `.git`. It does hold `.env.example`, `.gitignore`, `CLAUDE.md`, `README.md`, `docs/`, `tests/`, `requirements.*.txt` and `vendor/`: the build context copies the whole service tree (a finding for the Dockerfile, not a leak: no secret is among them). 3. **Key names and prefixes:** 0 matches for `OPENAI_API_KEY` or `sk-<chars>` in `docker history --no-trunc`, `docker image inspect` and `docker inspect` of the running container; its `Config.Env` holds only `PATH`, `LANG`, `GPG_KEY` (the base image's public Python release key id), `PYTHON_VERSION`, `PYTHON_SHA256`, `PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED`; its mounts are the `.env` as a **read-only bind** (`rw=false`) at `/app/.env` and the models **volume** at `/models`. 4. **Layers:** `docker save` listed 16,412 files (it does contain `app/main.py`) and the only `.env` entry is `app/.env.example`. 5. **User:** `Config.User` is empty and the process runs as uid 0 (root): a finding for [../../security/security.md](../../security/security.md), not fixed here (it is the generic Dockerfile of the `deployment` repository). All acceptance criteria met.
