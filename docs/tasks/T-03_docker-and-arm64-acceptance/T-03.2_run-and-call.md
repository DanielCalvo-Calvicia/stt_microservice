## Goal

Run stt in Docker with the **local** engine and the gate, see the run-time `prepare` step put the models into the volume, and transcribe the same phrase as in [T-01.1.3](../T-01_deployment-readiness/T-01.1_baseline-checks/T-01.1.3_real-transcription.md); then do the same with the OpenAI engine and the mounted `.env`.

## Read first

[T-01.1.3](../T-01_deployment-readiness/T-01.1_baseline-checks/T-01.1.3_real-transcription.md) (the WAV, the calls and the expected text), [T-02.3](../T-02_deployment-tool-changes/T-02.3_prepare-in-the-container.md), [T-02.4](../T-02_deployment-tool-changes/T-02.4_stt-catalogue-entry.md).

## Files

None changed. Settings go in the maintainer's git-ignored `deployment/config/local/stt.toml`.

## Steps

1. With the maintainer's yes, deploy with `STT_ENGINE = "local"` and `STT_GATE_ENABLED = 1` (`oblivion.py deploy --host <machine> -s stt`). Read in the output: the run-time `prepare` container (it should download the main model and the gate's into the volume and print "ready"), then the service container.
2. `docker --context desktop-linux ps` and `docker --context desktop-linux volume ls`: the container `oblivion-stt` is up and the volume `oblivion-stt-models` exists. `oblivion.py status --host <machine>` shows stt healthy.
3. `docker --context desktop-linux logs oblivion-stt`: `Loading local Whisper model on CPU` and `Local Whisper model loaded` twice, no download progress (the models were fetched by the prepare step).
4. Repeat the calls of T-01.1.3 steps 3 to 5 (probes, batch, gate) against the container's published address. Compare the text and the real-time factor with the native run.
5. Switch to `STT_ENGINE = "openai"` with the maintainer's key (ask first: it costs tokens), redeploy, repeat the batch call, and confirm `docker logs` shows `Calling OpenAI transcription API` and no key.
6. Restore the settings file.

## Acceptance criteria

- The volume holds both models after the `prepare` step; the service starts without downloading.
- The container transcribes the phrase with both engines and the gate answers with `audio_base64`.
- The container's published address, not `127.0.0.1` assumed, was used; the bind inside the container is `0.0.0.0` (the tool sets it for Docker, F9).

## Verification

The deploy output around the prepare step, `ps`, `volume ls`, the probe bodies, the text and the timings, in *Notes* (no key, no audio).

## Notes

Record the image's Python version (`docker exec oblivion-stt python --version`) and the real-time factor against the native one: a large gap means the container is CPU-limited (Docker Desktop's VM settings), not that the code is slower.

## Result (2026-11-09, steps 1 to 4 and 6; step 5, the OpenAI engine, not run yet: it costs tokens and waits for the maintainer's yes)

**Step 1, the run-time `prepare` container:** the deploy output shows `docker run --rm` with the `.env` as a read-only bind mount and `oblivion-stt-models` as a volume, then `Loading the main model small.en ... Main model small.en is ready`, `Loading the gate model tiny.en ... Gate model tiny.en is ready` (the Hugging Face "unauthenticated requests" notice is the only warning), then the service container and `stt: healthy and available`. **Step 2:** `oblivion-stt` Up on `127.0.0.1:8001->8001`, volume `oblivion-stt-models` created by this run (the pre-existing compose volume `oblivion-stt-model-cache` is not ours and was not touched). **Step 3:** the log shows `Loading local Whisper model on CPU` / `Local Whisper model loaded` twice (main, gate) 2.2 s after the start and no download line. The volume holds **539 MB** in the Hugging Face hub folder (`du` 551,212 KiB), `HF_HOME=/models/huggingface`, `SERVICE_HOST=0.0.0.0` (read from the mounted `.env`; the container's process environment has neither, so `docker exec ... printenv HF_HOME` prints nothing: the settings arrive through the file, and the note of T-03.3 step 5 that suggests `printenv` is wrong for this service).

**Step 4, calls** (`probe_stt.py` in the scratchpad, the phrase "Oblivion 306, what time is it" made with the SAPI voice, 22,050 Hz, 3.78 s): `/health` 200, `/available` 200 `is_available: true`, `/gate/available` 200 `true`. `POST /process/batch` 200 in **2.93 s** (real-time factor 0.78): ` Oblivion 306, what time is it?`; an empty body gives **400** `No audio data provided`. The gate: `stream_started`, `partial`, `completed` with `output='Oblivion 306. What time is it?'` and an `audio_base64` that decodes to exactly the 166,650 input bytes. For comparison the native `small.en` run of T-01.1.3 took 4.5 to 5 s per utterance (other phrases and a different machine load; the container is not slower). The published address was `127.0.0.1:8001` (the layout's single machine), and the bind inside is `0.0.0.0`.

**Step 6:** nothing to restore in `config/local`: the run used a scratch config folder.

The container log has **one** `Calling OpenAI transcription API` line.
