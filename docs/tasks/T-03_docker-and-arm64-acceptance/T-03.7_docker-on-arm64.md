## Goal

Build and run the stt image on arm64 (the Pi) and repeat the volume check there. The audit's dry-run showed that the packages resolve for aarch64 on Python 3.12 (F16); nothing was built on arm64.

## Read first

[T-03.1](T-03.1_amd64-build.md), [T-03.3](T-03.3_restart-without-redownload.md), [T-03.6](T-03.6_native-on-a-raspberry-pi.md), the preconditions of [T-03](T-03_docker-and-arm64-acceptance.md).

## Files

None changed.

## Steps

The Pi needs Docker installed (`doctor` says so). The tool runs on the Pi (or with `--remote`, if the maintainer prefers) with stt set to `runtime = "docker"` in the Pi's local settings; commands that call `docker` from the PC name the context: `docker --context raspberry ...`. The `raspberry` context timed out earlier for another service's checks and must be tested first with `docker --context raspberry info` (read-only).

1. Ask the maintainer. Build the image on the Pi (`deploy -s stt` there). Record the time (a long build is expected), the image size and `docker --context raspberry run --rm --entrypoint uname oblivion/stt:local -m` (`aarch64`).
2. Deploy with the local engine: the run-time `prepare` container downloads the models into the Pi's volume; the service starts; repeat the probes and the batch call of T-03.2 against the Pi's published address.
3. Repeat the restart and recreate checks of T-03.3 (steps 2 to 4).
4. Compare the real-time factor with the native one of T-03.6.

## Acceptance criteria

- The image builds on arm64 without compiling a dependency and the service answers `/available` and transcribes the phrase.
- A recreated container does not download again; the offline load from the volume succeeds.
- The Docker real-time factor is recorded next to the native one.

## Verification

The build lines, the architecture, the probes and the timings, in *Notes*.

## Notes

If building on the Pi is too slow or runs out of memory, say so; a cross-built image (`docker buildx`) is a separate decision and is not part of this plan.

**The Pi, from the maintainer (2026-11-06, [Q01](../../questionnaires/Q01_before-the-deployment-tasks.md) question 14):** Raspberry Pi 4B, 4 GB, 64-bit Raspberry Pi OS without a desktop; the Debian release is unknown, and it is **not known** whether Docker is installed or whether the `raspberry` context answers. Check both first (`docker --context raspberry info`) and stop with a clear message if not; the task then waits and the rest of the plan does not. With 4 GB, a build on the Pi may run out of memory (see above).
